# Signed Marketplace security and support advisories

Marketplace serves the current snapshot at `GET /api/v1/marketplace/security/advisories`. The response is an envelope whose `payload` is canonicalized with RFC 8785 and signed with Ed25519. The advisory signing key is configured independently from publisher, administrator, revocation and release-descriptor ingest tokens through `MARKETPLACE_ADVISORY_SIGNING_KEY_ID` and `MARKETPLACE_ADVISORY_SIGNING_PRIVATE_KEY_BASE64`. The corresponding public key must be provisioned out of band in each Core installation. Missing signing configuration makes the endpoint return `503`.

The payload has a monotonic `sequence`, UTC issue and expiry times, schema version, signer key ID, and one current entry per signed release. Entries keep support (`SUPPORTED`, `UNSUPPORTED`, `REMOVED`) and security (`ALLOWED`, `BANNED`) dimensions separate. They include the exact signed descriptor digest, every declared OCI digest, any banned subset, a severity, stable reason code and bounded plain-text EN/DE/FR/IT explanations. A whole-release ban includes all its image digests; an image-specific ban includes the selected exact digest, so Core can also block that image if it appears under another release or custom source.

Support changes and bans append immutable audit events. Publication unlisting publishes `REMOVED`; a security or malware revocation also publishes an exact digest ban. Other revocations publish `REMOVED` without classifying the release as unsafe. Marketplace does not contact Core. A six-hour feed refresh advances the sequence and renews snapshot freshness; operators may set `MARKETPLACE_ADVISORY_FEED_TTL` up to seven days. Core retains its last verified state if this feed is unavailable or expires, and displays stale status rather than restoring a prior allowed state.

Support status is changed with the admin credential at `POST /api/v1/admin/marketplace/releases/{releaseId}/support`. Exact release, image, or package bans use the separate revocation credential at the corresponding `/ban`, `/ban-image`, and `/plugins/{pluginId}/ban` routes. There is no ordinary unban route: lifting a ban requires a separately signed superseding event implemented through the key-rotation/incident process.

See [`signed-advisory-feed-v1.schema.json`](../marketplace-contract/signed-advisory-feed-v1.schema.json) and the shared Core contract documentation for the exact wire shape. Marketplace only publishes policy; Core independently verifies and locally enforces it.
