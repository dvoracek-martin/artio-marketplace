## Finding audit at baseline

| Finding | Baseline reproduction | Confirmed entry points / effect | Required disposition |
|---|---|---|---|
| A1 publication/supply-chain duties | Confirmed | `PublisherController` uses one publisher SHA-256 bearer verifier for all admin actions and writes actor `publisher`; Zot `publisher` can read/create/update/delete; marketplace ingress proxies `/` without an admin-network boundary. OCI verifier pins digest and one configured registry host, but not an approved repository prefix. No signing integration exists. | Separate publisher and moderation/revocation credentials and audit actor; deny Zot delete; constrain repositories; add admin ingress restriction and document signing as unimplemented. |
| A2 revocation foundation | Confirmed partial | Release revoke exists, but no release-specific public revoked response/latest exclusion policy or signed advisory contract. Existing revoke also mutates plugin-wide `listing_state`. | Keep revocation release scoped, stop recommending revoked releases, add signed future feed contract only; no remote disable/kill switch. |
| A3 state separation | Confirmed | `marketplace_plugins.listing_state` represents `LISTED/UNLISTED/REVOKED`; publish sets `LISTED`; unlist/revoke a single release sets plugin-wide state. Publishing a later release can restore `LISTED`. V1 has no separate plugin moderation state. | Add V2 migration, distinct moderation/release state, transition/CAS rules and data review for ambiguous old `REVOKED` records. |
| A4/A5 proxy IP and rate limiting | Confirmed | `ApiRateLimitFilter.clientAddress` chooses the leftmost XFF value; trusted proxies are exact strings only. Bucket cap rejects new clients at capacity until periodic cleanup; no global admission policy. Nginx uses `$proxy_add_x_forwarded_for` and does not sanitize inbound chain. | Parse right-to-left against explicit exact/CIDR trusted hops, sanitize at edge, evict expired/LRU state safely, add global cap and real-proxy tests. |
| A6 acceptance CI gate | Confirmed | `.github/workflows/ci.yml` has `continue-on-error: true` on the live acceptance step. The known Core controller test failure therefore does not make the run red. | Remove suppression; keep diagnostic/teardown and independent scans; add a controlled failure-gate test; allow the unresolved mandatory Core test to make the gate red. |
| A7 Zot retention | Confirmed | `deployment/zot/config.json` has `storage.gc: true`; ordinary publisher actions include `delete`. PostgreSQL references are not known to Zot GC. | Disable automatic GC and publisher delete; document retention invariant and test digest pulls across restart/restore. |
| A8 untrusted text | Confirmed partial | `ManifestRules` applies `rejectUnsafeText` to catalog only. Core manifest strings, config labels/descriptions, and other public text are not covered by a bounded Marketplace policy. | Reject unsafe text on all user-facing values without mutating canonical manifest; preserve Unicode; test malformed/deep/large payloads and media attacks. |
| A9 SemVer selection | Confirmed partial | `latestCompatible` filters then uses SemVer, but catalog cards, plugin details and release pages choose/sort by `published_at DESC`; a hotfix published later can replace a numerically higher version and Core compatibility is not applied consistently. | Centralize state/Core/geo/channel eligibility and SemVer ordering across listing/detail/latest/pagination. |
| A10 catalog update response | Confirmed | `replaceCatalog` ignores the affected row count from the `DRAFT/VALIDATED` CAS update, then audits success and returns a draft for immutable releases. | Return 404 for absent, 409 for immutable/state conflict; audit only successful committed mutation; concurrency regression tests. |
| A11 actuator/security boundary | Confirmed | `SecurityConfiguration` uses `anyRequest().permitAll()`; actuator exposes `health,info,prometheus`; proxy marketplace server has `location /` with no actuator/admin denies. Health details are currently hidden. | Deny by default, exact public route/method allowlist, protect management and management proxy routes; direct and proxy acceptance tests. |
| A12 registry HTTP transaction duration | Confirmed | `PublisherController.create` and `publish` are `@Transactional` and call the HTTP `ArtifactVerifier` within those methods; verifier can spend up to eight seconds per image/sidecar. | Move orchestration to durable reserve/verify/finalize phases with external I/O outside transactions, CAS/state revalidation, safe retries and latency/concurrency tests. |

## Progress and evidence

Hardening started from Marketplace baseline `0f1d76e42908978911c7b10667827e033b38bc19`; Artio Core remains untouched. The original implementation's hosted baseline and known Core controller fixture failure are documented above and in [acceptance evidence](ACCEPTANCE.md).

### Local hardening evidence (2026-10-16)

| Finding | Implementation/evidence | Status and remaining risk |
|---|---|---|
| A1 | Three API credentials use separate hashes/actors; configured hashes must be unique. Zot push cannot delete; OCI references are host/repository allowlisted and digest-verified. V3 adds a distinct admin approval of the exact manifest and catalog hashes between publisher staging and publication. Catalog edits clear approval. | **Mitigation implemented; live Docker regression pending.** A single publisher or admin API token alone cannot publish code. Cosign/Sigstore signing, verified provenance, person-level identity, and customer Core-side signature enforcement remain absent; approval is an out-of-band human review boundary, not cryptographic provenance. |
| A2 | Release revocation is immutable and release-scoped, returns 410, removes only that version from recommendations, and preserves sibling versions. `docs/FUTURE_CORE_REVOCATION.md` describes the cross-repository signed feed boundary. | **Critical Core blocker remains.** Marketplace has no customer Core connections, and Core does not poll revocation advisories; already installed plugins continue running. A separate Core implementation is required to notify/enforce revocation. |
| A3 | V2 separates moderation/release states and quarantines ambiguous legacy REVOKED plugins to REVIEW_REQUIRED with audit. Docker acceptance verifies sibling availability, suspension hiding, and rejected new publication while suspended. | **PASS locally.** A live upgrade on a production-sized database is not claimed; take/verify backups before deployment. |
| A4/A5 | Trusted proxy CIDR/exact-hop parsing right-to-left; sample XFF sanitization; public/publisher and global caps; expiry/LRU eviction. Regression tests cover spoofed leftmost XFF and admission after 20,000 distinct buckets. The `.env.example` now requires operators to replace the trusted-peer placeholder. | **PASS for the algorithm; deployment configuration is mandatory.** If a proxy peer is omitted, its clients share the socket-peer bucket. Multi-replica distributed rate limiting is not implemented; remain single API replica. |
| A6 | Required acceptance no longer uses `continue-on-error`; diagnostics/scans/teardown remain separate; controlled injected-failure self-check exits nonzero. | **Fail-closed behavior verified.** Hosted run [38833700448](https://github.com/dvoracek-martin/artio-marketplace/actions/runs/38833700448) correctly failed on pinned Core `PackagedExtensionControllerIntegrationTests.packagedControllerAuthenticatesAndManagesPrivateBundleWithoutCommerceServices` (Core line 146 NPE); restore, SBOM generation, Trivy, and teardown still ran. CI remains red until that separately scoped Core issue is fixed. |
| A7 | Zot GC is off and publisher delete is denied. Docker acceptance publishes/pulls main and sidecar artifacts by digest; backup/restore drill recreates only its named test volumes, restores PG/Zot/media, compares the exact manifest and pulls its digest. | **PASS for GC-disabled retention and tested restore.** No GC algorithm is enabled or claimed safe; registry storage grows and requires disk/backup monitoring. |
| A8 | Shared bounded text rules reject markup, unsafe schemes, controls, excessive text/tree limits across catalog and Core manifest including configuration labels; Unicode remains intact. | A9 | One SQL release-selection policy filters plugin/release state, prerelease, Core range and country before SemVer selection for lists/details/exact/latest-compatible; migration SQL defines numeric SemVer key. | **PASS locally.** Docker acceptance verified stable/prerelease ordering and Core-compatible fallback across paginated release results. |
| A10 | Catalog replacement uses row-version/state CAS and writes audit only on committed update. | **PASS locally.** Acceptance confirmed immutable update returns 409 and does not add an audit row; concurrent live multi-writer stress was not run. |
| A11 | Security is deny-by-default; separate management port; public Nginx denies actuator. | **PASS locally for tested routes.** Direct requests to prometheus/env/mappings/configprops/heapdump/logfile/metrics returned 403/404, and the proxy returned 404 for actuator. |
| A12 | External OCI verification is before short PostgreSQL reserve/finalize transactions; publication uses PUBLISHING + CAS, moderation/media recheck and a 15-minute reservation recovery. | **Implementation and successful OCI publication verified.** Automated registry timeout, process-crash, and concurrent revoke/publish fault-injection tests remain unimplemented; these are still release risks and not claimed as proven. |
