# Architecture

The Gradle project separates `marketplace-domain`, `marketplace-application`, `marketplace-contract`, `marketplace-infrastructure` and `marketplace-server`. Domain value objects are framework-free. Application defines ports. Infrastructure provides PostgreSQL/Flyway, filesystem media storage and a constrained Zot OCI verifier. Spring MVC and the publisher-token check live at the HTTP edge.

Core owns the runtime manifest contracts. Marketplace preserves the original `PluginManifest v1` unchanged and accepts the v5.1 capability-envelope v2 contract, which wraps package metadata under `packageManifest` and carries capabilities/subscriptions at the envelope root. Catalog metadata remains a separate `CatalogMetadataV1` JSON document with `schemaVersion: 1`; it is stored beside the unmodified runtime manifest and is never merged into it. Plugin moderation states (`ACTIVE`, `SUSPENDED`, `BANNED`, `REVIEW_REQUIRED`) are distinct from release publication states (`DRAFT`, `VALIDATED`, `PUBLISHING`, `PUBLISHED`, `UNLISTED`, `REVOKED`) and from Artio Core install/enable states. An old ambiguous plugin-wide `REVOKED` is migrated to `REVIEW_REQUIRED` for an operator decision. Manifest v2 is independent of REST API versions; Core calls remain under `/api/v1` throughout development.

Release publication uses a two-party credential workflow and durable phases. A publisher stages an immutable request and supplies assets; a separate admin reviews the admin-only draft view and approves the exact manifest and catalog hashes with an audit reason. Catalog edits clear approval. The publisher credential is then required to reserve `PUBLISHING` by CAS in PostgreSQL, verify all main/sidecar OCI digests over HTTP with no database transaction open, recheck media and plugin moderation, then finalize by CAS and append audit. Neither one API token can stage/approve/publish alone. Failed checks release the reservation; a 15-minute lease recovery returns an abandoned reservation to `VALIDATED`. Idempotency keys make create retries safe; publication retries are safe after the durable reservation completes or expires. The Marketplace has no Docker socket and never starts customer extensions.

The Marketplace is a central distribution service for many independent Artio Core installations. It stores shared public catalog/releases and has no per-customer Core connection, callback, credentials, or runtime state. Core installations read public Marketplace APIs; their Docker daemons pull digest-pinned images directly from the public Zot hostname. An outage can prevent new discovery/pulls, but does not interrupt a plugin already installed and running under Core. CI may build a pinned Core checkout to run isolated contract/runtime tests; this is not a deployed Core instance or a Marketplace-to-Core connection.

The packaged container runs Spring Boot as PID 1 and starts the pinned Zot binary as a supervised child using Spring `SmartLifecycle`. It observes child termination, exits nonzero if Zot unexpectedly exits, forwards graceful shutdown and reaps the child. PostgreSQL runs separately. The reverse proxy terminates TLS and routes public Marketplace host traffic to 8080 and registry host traffic to 5000. Management probes use separate loopback-bound host port 8081; the Internet-facing proxy denies `/actuator/`.

The in-process rate limiter honors X-Forwarded-For only for configured exact/CIDR proxy peers and walks the chain from the trusted socket peer toward the first untrusted hop. The sample Nginx edge overwrites forwarded addresses with `$remote_addr`; deployment must configure the actual proxy peer in `MARKETPLACE_RATE_LIMIT_TRUSTED_PROXIES`. If proxy peers are not trusted, all clients behind one proxy share its socket-peer bucket. Per-client buckets expire and use LRU eviction under a fixed memory cap; independent public and publisher global windows provide admission ceilings. Multi-replica deployment requires shared media and a distributed rate limiter.
